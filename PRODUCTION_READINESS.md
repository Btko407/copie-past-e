## Build Command Sequence

**Order matters.** The frontend declarations are generated from the compiled
backend DID. Running `pnpm bindgen` before `mops build` produces broken output.

```bash
# 1. Install backend dependencies
cd src/backend
mops install

# 2. Build backend — generates src/backend/dist/backend.did
mops build

# 3. Install root-level dependencies
cd ../..
pnpm install --prefer-offline

# 4. Generate frontend TypeScript declarations from backend.did
#    (scripts/bindgen-check.sh will fail loudly if backend.did is missing)
pnpm bindgen

# 5. Install frontend dependencies
cd src/frontend
pnpm install --prefer-offline

# 6. TypeScript typecheck
pnpm typecheck

# 7. Production build
pnpm build
```

## Canister ID / Host Wiring

- The canister ID is set at deployment time by the Caffeine platform.
- At runtime, `env.json` in the frontend is populated by the platform's
  `copy:env` step — this file is intentionally all `"undefined"` in source
  control and must never be committed with real values.
- All actor calls from the frontend flow through
  `src/frontend/src/backend.ts` — this file is **generated by bindgen**
  and must not be edited manually.
- The actor host is resolved from `env.json` at runtime.

## Deployment

Deployment is managed by the Caffeine platform ([caffeine.ai](https://caffeine.ai)).

- The platform reads `caffeine.toml` at the repository root for service
  ordering (`frontend` depends on `backend`).
- **Never deploy the frontend before the backend.** The bindgen declarations
  must be in sync with the live canister DID.
- After every backend API change, run `mops build && pnpm bindgen` and
  commit the updated `backend.ts` / `backend.d.ts` before deploying.

## Architecture: Why No Webhooks

ICP canisters **cannot receive inbound HTTP requests** from external services.
Stripe webhooks require an externally-reachable HTTP endpoint — which a
canister is not.

**Stripe payment flow on ICP (polling-based):**

1. User clicks "Buy" → frontend calls `createCheckoutSession(priceId)` on canister
2. Canister calls Stripe API via HTTPS outcall → returns checkout session URL
3. Browser redirects to Stripe checkout page
4. User pays on Stripe
5. Stripe redirects browser to `/payment-success?session_id=XXX`
6. Frontend calls `verifyAndGrantPayment(sessionId)` on canister
7. Canister calls `GET /v1/checkout/sessions/{id}` on Stripe
8. If `payment_status == "paid"` → subscription days are added additively
9. Frontend displays updated subscription status

The `pendingSessions` stable variable prevents duplicate grants — a session
can only be verified once per user.

## Cycles Budget

ICP HTTPS outcalls consume cycles from the canister balance. If cycles run
out, **all functionality stops** — including payments and OCR.

| Operation | Cycles attached |
|---|---|
| Gemini OCR scan (POST with image) | 100,000,000,000 (100B) |
| Gemini test connection | 21,000,000,000 (21B) |
| Stripe checkout create (POST) | 49,140,000,000 (49B) |
| Stripe verify payment (GET) | 20,949,972,000 (≈21B) |
| Stripe test connection (GET) | 20,949,972,000 (≈21B) |

**Monitor:** Admin panel → Debugger → Canister Cycles Balance  
**Warning threshold:** < 1,000,000,000,000 cycles (1 trillion)  
**Action on low cycles:** Top up the canister via the Caffeine dashboard.

All outbound calls use `is_replicated = ?false` (non-replicated outcalls).
This means a single replica makes each request — no ICP consensus is required
on the response. This is correct for non-deterministic external APIs (Gemini,
Stripe) where responses differ between replicas.

## Running Locally (Type-check Only, No Replica Needed)

Full local ICP development requires `dfx` running with a local replica.
For type-checking and build validation only:

```bash
# 1. Motoko typecheck (no replica needed)
cd src/backend
mops check --fix

# 2. Compile DID (no replica needed)
mops build

# 3. Regenerate frontend declarations
cd ../..
pnpm bindgen

# 4. TypeScript typecheck
cd src/frontend
pnpm typecheck
```

## CI Pipeline Summary

See `.github/workflows/ci.yml` for the full definition.

```
push/PR
  │
  ▼
Job 1: backend-check          (ubuntu-latest)
  mops install → mops check --fix → mops build
  uploads: backend.did artifact
  │
  ▼ (needs: backend-check)
Job 2: bindgen-validation     (ubuntu-latest)
  downloads: backend.did
  pnpm install → pnpm bindgen
  git diff --exit-code backend.d.ts  ← FAILS with actionable message on drift
  uploads: backend.ts + backend.d.ts artifacts
  │
  ▼ (needs: bindgen-validation)
Job 3: frontend-check         (ubuntu-latest)
  downloads: frontend-declarations
  pnpm install → pnpm typecheck → pnpm build
```

Jobs run sequentially with `concurrency` cancellation on new pushes.
A declaration drift error in Job 2 means the backend API changed but
`pnpm bindgen` was not run locally before committing.

## Remaining Risks

| Risk | Mitigation |
|---|---|
| Cycles exhaustion mid-payment | Monitor admin Debugger; top up before balance drops below 1T |
| Stripe API key rotation | Re-save new keys in admin Payments; old key fails immediately on test |
| Gemini model deprecation | Update model name in `ocr-api.mo`; currently `gemini-2.5-flash-lite` |
| Schema changes in stable vars | Add migration stubs in `system_upgrade` hook before deploying breaking changes |
| `backend.d.ts` drift in CI | Job 2 of CI pipeline catches this; blocked until dev runs `pnpm bindgen` and commits |

## Subscription Time Formula

For any paid tier:

```
newExpiration = max(currentExpiration, now()) + tierDays * 86_400_000_000_000
```

- Time always **stacks additively** — buying while active extends from the current expiration date
- Duplicate `verifyAndGrantPayment` calls for the same session are idempotent (session deleted after first grant)
- Tier days: Time Walker = 30, Time Traveler = 90, Time Lord = 180
